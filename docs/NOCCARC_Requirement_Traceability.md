# NOCCARC assignment requirement traceability

Scope is the official STM32H743 four-node assignment PDF. The supplemental Codex execution brief requests the submission documents and verification matrix. Proposed protocol upgrades are tracked separately from PDF requirements.

| PDF section | Requirement | Status and evidence |
|---|---|---|
| 1–2 | Four independent STM32H743 nodes on one shared CAN FD bus, each owning five values | **PASS — verified in Renode.** Four `NODE_ID` builds of [main_network.c](../src/main_network.c) run as separate [machines](../renode/network.resc). Each broadcasts directly. |
| 1–2 | MCU1 collects network health and sends its local database over UART | **PASS — verified in Renode.** The MCU1 branch calls [Telemetry_Service](../src/telemetry.c). Both recovery runs check DMA completions and decode the captured snapshots. |
| 3 | CAN FD, 500 kbit/s arbitration, 2 Mbit/s data, BRS, up to 64-byte capability | **PASS — configured in firmware and logically verified in Renode.** [Timing profile](../system/inc/peripheral_config.h) and [FDCAN driver](../system/src/FDCAN.c). The application sends 4- and 24-byte frames. Physical rates are outside the simulation requirement. |
| 3 | Identifiers, layouts, encoding, transmission period, sequence, validation, error handling, heartbeat, timeout and recovery | **PASS.** [Application TX/RX](../src/main_network.c) and [state](../src/network_state.c). See the architecture document for exact layouts and the verification matrix for actual malformed and duplicate RX cases. |
| 4 | All 20 values on each node, one authoritative owner, value and metadata | **PASS — verified in Renode.** [NetworkState](../src/network_state.h) holds four five-value groups. ID and owner derive from the array indices. Sequence, update tick and validity are shared by the five values sent in a group. Freshness derives from age. All receiver databases were checked directly. |
| 5 | Deterministic bare-metal, static memory, interrupt RX, bounded application work, clear module ownership | **PASS for the application architecture.** [FDCAN port](../system/src/FDCAN_Port.c) signals RX from the ISR. [Main](../src/main_network.c) owns database writes and bounds RX to eight frames per pass. The existing DMA driver has synchronous stream-disable waits, listed as a hardening gap. |
| 6 | Heartbeats, delayed/missing status, timeout, missed count, restart and resynchronization | **PASS for the required operating scenario.** [State logic](../src/network_state.c) and both measured Renode runs. During isolation all three healthy nodes invalidate MCU3's group and keep their other groups fresh. |
| 7–8 | Linux, four running MCU instances, shared logical CAN FD, MCU1 UART and reproducible setup | **PASS on the installed Renode build.** [Platform](../renode/assignment.repl), [launcher](../renode/network.resc), [Makefile](../Makefile), [instructions](../README.md). Physical layer behavior is excluded by PDF §7.1. |
| 9–9.1 | Exactly three dashboard sections with actual validated values and all required labels | **IMPLEMENTED; live browser evidence BLOCKED here.** [Browser code](../dashboard/index.html) shows overall health, four MCU rows with heartbeat age, timeout and recovery, and 20 parameter rows with value, source, freshness and validity. Generated replay uses captured MCU1 snapshots. |
| 10 | UART format, validation, update cadence and link-loss handling | **PASS for transport and decoder; live rendering BLOCKED here.** [UART encoder](../src/telemetry.c), [parser](../dashboard/protocol.py), [monitor](../dashboard/monitor.py). CRC-valid DMA snapshots and previous PTY link-loss/recovery verified. |
| 11 | Source, binaries, protocol and architecture documentation, scripts, logs and dashboard evidence | **PARTIAL.** Source, four images, report, scripts, test logs and replay are present. A live browser screenshot or recording remains to be collected on the developer machine. |
